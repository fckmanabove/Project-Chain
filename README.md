## 🎯 Бизнес-контекст и решаемая проблема

На современных промышленных предприятиях (деревообработка, мебельные фабрики, машиностроение) модернизация цехов ведётся параллельно по нескольким взаимосвязанным проектам. До внедрения ProChain управление велось в разрозненных файлах Excel с макросами VBA, что приводило к:
1. **Скрытым срывам сроков:** отсутствие автоматического пересчёта критического пути при сдвиге промежуточных этапов.
2. **Конфликтам ресурсов и оборудования:** одновременное назначение ключевых инженеров (АСУ ТП, пусконаладка) на параллельные задачи и наложение работ на одной физической линии (цеховые коллизии).
3. **Состоянию гонки (Race Condition):** затирание данных при одновременной правке файлов несколькими специалистами.
4. **Потере исторического контекста:** невозможность быстро понять первопричину задержки и отсутствие возможности безопасного отката (Undo).

**Project-Chain** объединяет календарные графики, паспорта проектов, цеховой журнал производства работ и систему контроля рисков в единый синхронизированный контур.

## 🏛 Ключевые инженерные решения

### 1. Собственное математическое ядро CPM Engine (DAG)
* График проекта представляется как **ориентированный ациклический граф (DAG)** на базе `NetworkX`.
* **Forward Pass (Прямой проход):** расчёт ранних стартов и финишей ($ES, EF$) с учётом 4 типов связей (`FS`, `SS`, `FF`, `SF`) и временных лагов ($Lag$).
* **Backward Pass (Обратный проход):** расчёт поздних дат ($LS, LF$), полного резерва времени ($Total\ Float$) и свободного резерва ($Free\ Float$).
* **Критический путь:** автоматическое выделение цепочек задач с нулевым резервом ($Total\ Float \le 0$).
* **Защита от дедлоков:** детекция циклических зависимостей с формированием читаемого пути ошибки (`CPMGraphCycleError`).
* **Производственный календарь:** расчёт рабочих дней по графикам 5/2, 6/1, 7/0 с пропуском официальных праздников и учётом рабочих суббот.

### 2. Распределённые живые блокировки (Redis Live Locks)
* Защита от коллизий при одновременном редактировании графика несколькими инженерами.
* Атомарный захват, освобождение и продление блокировки через **Lua-скрипты**:
  ```lua
  if redis.call("get", KEYS[1]) == ARGV[1] then
      return redis.call("del", KEYS[1])
  else
      return 0
  end
  ```
* Механизм **Heartbeat**: TTL ключа блокировки (30 сек) продлевается, пока открыта карточка задачи.
* Идемпотентность: повторный вход того же пользователя продлевает существующую блокировку без ошибки `423 Locked`.

### 3. Time Machine: Версионирование и 1-клик откат (Undo / Undelete)
* Сервис `AuditService` автоматически снимает снимки состояния до (`before_state`) и после (`after_state`) любой мутации в `JSONB`.
* Вычисление человекочитаемой дельты изменений (`generate_diff_summary`): *«Финиш: 17.06.26 ➔ 30.09.26; Ответственный: Иванов ➔ Климов»*.
* **1-Click Rollback:** откат обновлений (возврат значений полей), откат созданий (удаление) и воскрешение сущностей из **Корзины удалений (Undelete)**.
* Поддержка полного отката массового импорта файлов Excel (`EXCEL_IMPORT`) с каскадной очисткой созданных задач.

### 4. Векторный семантический поиск инцидентов (pgvector)
* Модуль `SnapshotCollector` агрегирует числовые метрики задержек и текстовый контекст из цехового журнала работ.
* Хранение 1536-мерных векторов в колонке `VECTOR(1536)` PostgreSQL.
* Поиск похожих исторических аварий и инцидентов через косинусное расстояние (`cosine_distance`) с обязательной изоляцией в рамках разрешённых проектов.

### 5. Двусторонний Excel-мост (Universal Excel Bridge)
* Автоматическое распознавание умных таблиц (`tblM06Data`, `03_M06_Данные`, `_02_ПортфельЭтапов`).
* **Интерактивный Diff Preview:** сравнение входящей книги с базой PostgreSQL на бэкенде, фильтрация неизменённых строк и показ дельты пользователю.
* **Выборочное применение (Selective Apply):** обновление только утверждённых галочками этапов.
* **Actuals Protection (MVP DNA):** защита базового плана от затирания старыми файлами — фактически начатые или завершённые на производстве работы не сбрасываются.
* Выгрузка базы в эталонный формат умной таблицы `tblM06Data` (.xlsx) для полной обратной совместимости.

### 6. Комплексная безопасность (Defense-in-Depth)
* **Zero-Trust аутентификация:** все эндпоинты закрыты гвардами матрицы RBAC (`require_permission`).
* **Двухфакторная защита (2FA):** генератор числовых OTP через нативный SMTP-клиент + Google Authenticator (RFC 6238 TOTP).
* **Защита от брутфорса:** скользящее окно rate-limiting в Redis и автоматическое сгорание OTP (Auto-burn) после 5 неверных попыток ввода.
* **JWT Blacklist:** мгновенный отзыв сессий через внесение `jti` в Redis до истечения `exp`.
* **Защита от инъекций:**
  * Санитизация формульных инъекций в CSV (CWE-1236): экранирование управляющих символов `=`, `+`, `-`, `@`.
  * Защита от выхода за пределы каталога при распаковке архивов (CWE-22 Zip Slip).
  * HTTP-заголовки: строгая политика `Content-Security-Policy`, `X-Frame-Options: SAMEORIGIN`, `nosniff`, `Referrer-Policy`.

### 7. Высокопроизводительный фронтенд
* Плотная компоновка Гантта (высота строки 28px) — комфортно отображает до 50 задач на одном экране без прокрутки.
* **Zero-Latency Drag-to-scroll:** панорамирование таймлайна «рукой» через `setPointerCapture` без тяжелых React-ререндеров.
* Двухъярусная шапка календаря: дни месяца объединяются в сплошные блоки (`СЕН 2026`), исключая обрезку текста при узком масштабе (до 14px на день).
* Свободный ресайз колонок таблицы мышкой и растягивание ширины всего Гантта за правый край.
* Floating HUD: свободно перетаскиваемый пульт навигации с возможностью докинга к правому краю экрана.
* Поддержка двух тем оформления: **Industrial Dark** и **Excel Clean** с плавной анимацией круговой волны (*Telegram-style View Transitions API*).
* Встроенный интерактивный обучающий квест для техлида на **driver.js**.

### Вариант 2. Нативный локальный запуск (venv + npm)

#### Требования:
* Python 3.11+
* Node.js 20+
* Запущенные локально PostgreSQL (с расширением pgvector) и Redis

#### 1. Бэкенд:
```bash
# Создаём виртуальное окружение
python3 -m venv .venv
source .venv/bin/activate

# Устанавливаем зависимости
pip install -r backend/requirements.txt

# Накатываем структуру таблиц и сидируем портфель проектов
cd backend
python -c "
import asyncio
from app.core.init_auth_db import init_auth_db
from scripts.import_portfolio_xlsm import import_portfolio
from scripts.seed_cpm_dependencies import seed_dependencies
from scripts.seed_p003_diary import seed_diary

async def bootstrap():
    await init_auth_db()
    await import_portfolio()
    await seed_dependencies()
    await seed_diary()
    print('✅ База данных готова!')

asyncio.run(bootstrap())
"

# Запускаем сервер FastAPI
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

#### 2. Фронтенд (во втором терминале):
```bash
cd frontend
npm install
npm run dev
```
